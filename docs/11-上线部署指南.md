# 上线部署指南：把项目变成可访问的网站

> 文档编号：docs/11
> 适用版本：`00396dc`
> 目标：从「本机跑通」到「别人点链接就能用」

---

## 0. 先选路线

| 路线 | 拿到链接的时间 | 成本 | 适合 | 主要限制 |
|---|---|---|---|---|
| **A. 本机 + 内网穿透隧道** | 10 分钟 | 0~30 元/月 | 演示、给朋友试、答辩 | 本机关机即失效；带宽与稳定性差 |
| **B. 云服务器 + Docker Compose**（推荐） | 1~2 小时（不含备案） | 60~150 元/月 | 长期使用、真实用户 | 大陆服务器绑域名需备案 |
| **C. PaaS 托管**（Render/Railway/Fly） | 30 分钟 | 0~20 美元/月 | 海外访问、快速验证 | 大陆访问慢；WebRTC 仍需自建 TURN |

> 语音与视频依赖 **HTTPS/WSS**（浏览器只在安全上下文允许麦克风摄像头），
> 所以无论哪条路线，**必须 HTTPS**，不能只开 http。

---

## 1. 路线 A：本机 + 隧道（最快拿到链接）

原理：隧道服务在你的电脑和公网之间建一条加密通道，给你一个 https 域名。

以 **Cloudflare Tunnel** 为例（免费、自带 https、支持 WebSocket）：

```powershell
# 1. 安装 cloudflared（Windows）
winget install --id Cloudflare.cloudflared

# 2. 登录（浏览器授权一次）
cloudflared tunnel login

# 3. 创建隧道并拿到域名
cloudflared tunnel create ai-interview

# 4. 把本地两个端口映射出去（前端 5173，后端 8080）
#    最简做法：只暴露前端，Vite 已把 /api 与 /ws 代理到后端
cloudflared tunnel route dns ai-interview interview.example.com
cloudflared tunnel run --url http://localhost:5173 ai-interview
```

或者一步到位的临时链接（不用域名，重启就变）：

```powershell
cloudflared tunnel --url http://localhost:5173
# 输出形如 https://xxxx-xxxx.trycloudflare.com
```

同时启动：

```powershell
# 终端 1
java -jar target\ai-interview-platform.jar
# 终端 2
cd web; npm run dev
```

**注意事项**

- 前端 `npm run dev` 的 Vite 代理负责把 `/api`、`/ws` 转给 8080，隧道只映射 5173 即可；
- 隧道域名必须是 https，麦克风权限才可用；
- 本机睡眠/断网就掉线，不适合长期运营；
- 演示前先自己用手机 4G 打开链接试一次（验证不是局域网侥幸）。

## 2. 路线 B：云服务器 + Docker Compose（推荐长期）

### 2.1 买服务器

| 项 | 建议 |
|---|---|
| 厂商 | 阿里云 / 腾讯云 轻量应用服务器 |
| 规格 | **2 核 4G** 起（Java + MySQL + Redis 同机） |
| 系统 | Ubuntu 22.04 LTS |
| 磁盘 | 40G+（音频与日志） |
| 带宽 | 3~5 Mbps（视频是 P2P，服务器只转发信令，不吃带宽） |
| 安全组 | 放行 22、80、443；**TURN 需要 3478/udp+tcp 与 49152-65535/udp** |

> 视频媒体走 WebRTC P2P，服务器只承担信令；真正吃带宽的是「跨 NAT 失败时的 TURN 中继」，
> 所以 TURN 建议单独放一台小机器或限制使用。

### 2.2 域名与备案（大陆服务器必须）

1. 买域名并完成实名认证；
2. 在云厂商控制台提交 **ICP 备案**（7~20 个工作日）；
3. 备案通过前可以先用 **IP + 端口** 访问，但**没有 HTTPS 就没有麦克风权限**，等于语音/视频不可用；
4. 不想备案 → 选香港/新加坡地域（免备案，但大陆访问延迟高）。

### 2.3 安装环境

```bash
# Ubuntu 22.04
sudo apt update && sudo apt -y upgrade
# Docker + Compose 插件
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER && newgrp docker
docker --version && docker compose version
```

### 2.4 上传代码

```bash
# 服务器上
sudo mkdir -p /opt/ai-interview && sudo chown $USER /opt/ai-interview
cd /opt/ai-interview
git clone https://github.com/houtianyu466-beep/ai-interview-assistance.git .
```

如果服务器访问 GitHub 慢，可在本机打包后上传：

```powershell
# 本机
git archive --format=zip -o ai-interview.zip HEAD
scp ai-interview.zip root@服务器IP:/opt/ai-interview/
# 服务器
cd /opt/ai-interview && unzip -o ai-interview.zip
```

### 2.5 构建前端并放到 Nginx 目录

```bash
cd /opt/ai-interview/web
npm ci || npm install
npm run build          # 产出 web/dist
```

> 也可以在**本机**构建好，只上传 `web/dist`，服务器就不用装 Node。

### 2.6 配置环境变量

```bash
cd /opt/ai-interview/deploy
cp .env.example .env
nano .env
```

必填项：

| 变量 | 说明 |
|---|---|
| `APP_DOMAIN` | 你的域名 |
| `MYSQL_ROOT_PASSWORD` / `DB_PASSWORD` | 数据库强密码（两处一致） |
| `REDIS_PASSWORD` | Redis 密码 |
| `APP_JWT_SECRET` | ≥32 位随机串，**必须改** |
| `DEEPSEEK_API_KEY` | 对话/Agent |
| `APP_ASR_API_KEY` | 语音转写（硅基流动） |
| `APP_EMBEDDING_API_KEY` | 向量检索（硅基流动） |
| `APP_DEMO_DATA_ENABLED` | 首次启动 `true`，建好账号后改 `false` |
| `APP_ICE_SERVERS` | 见 2.9 TURN |

生成随机 JWT 密钥：

```bash
openssl rand -base64 48
```

### 2.7 证书

**方式一：云厂商免费证书（最省事）**

控制台申请 → 下载 Nginx 格式 → 上传到服务器：

```bash
mkdir -p /opt/ai-interview/deploy/certs
# 把下载的 .pem / .key 传上去并重命名
scp fullchain.pem privkey.pem root@服务器IP:/opt/ai-interview/deploy/certs/
```

**方式二：Let's Encrypt（自动续期）**

```bash
sudo apt -y install certbot
# 先停 nginx（compose 里的），用 standalone 签证书
cd /opt/ai-interview/deploy && docker compose stop nginx
sudo certbot certonly --standalone -d interview.example.com
sudo cp /etc/letsencrypt/live/interview.example.com/fullchain.pem certs/
sudo cp /etc/letsencrypt/live/interview.example.com/privkey.pem certs/
# 续期：certbot renew --pre-hook "docker compose stop nginx" --post-hook "docker compose start nginx"
```

### 2.8 改 Nginx 域名并启动

```bash
# 把配置里的 interview.example.com 换成你的域名
sed -i 's/interview\.example\.com/你的域名/g' nginx/ai-interview.conf
docker compose up -d --build
docker compose ps
docker compose logs -f app | head -50
```

看到 `The following 1 profile is active: "prod"` 且无异常即启动成功。

### 2.9 TURN（跨网络视频必需）

只配 STUN 时，同城/同网可以连通；双方都在严格 NAT（公司网、4G）下会连不上，
表现为「一直显示正在连接对方」。

```bash
# 装 coturn
sudo apt -y install coturn
sudo sed -i 's/#TURNSERVER_ENABLED=1/TURNSERVER_ENABLED=1/' /etc/default/coturn
```

`/etc/turnserver.conf`：

```ini
listening-port=3478
fingerprint
lt-cred-mech
realm=interview.example.com
user=interview:请替换为强密码
# 公网 IP（必填，否则中继地址错误）
external-ip=你的公网IP
min-port=49152
max-port=65535
no-multicast-peers
```

```bash
sudo systemctl restart coturn
sudo systemctl status coturn
```

然后在 `deploy/.env` 里把 ICE 改成带账号密码的形式：

```ini
APP_ICE_SERVERS=turn:interview:请替换为强密码@interview.example.com:3478
```

> 当前代码的 `app.video.ice-servers` 只支持**字符串 URL**，所以 TURN 凭据要按
> `turn:用户名:密码@主机:端口` 的写法塞进 URL（浏览器支持这种写法）。
> 若要更规范（独立 username/credential 字段），需要扩展 `VideoProperties` 为结构化配置。

安全组/防火墙要放行：`3478/tcp`、`3478/udp`、`49152-65535/udp`。

### 2.10 数据持久化与备份

| 数据 | 位置 |
|---|---|
| MySQL | 命名卷 `mysql-data` |
| Redis | 命名卷 `redis-data` |
| 上传的简历/音频 | 命名卷 `app-data`（容器内 `/app/data`） |

备份：

```bash
docker compose exec mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" ai_interview' > backup_$(date +%F).sql
docker run --rm -v deploy_app-data:/data -v $PWD:/backup alpine tar czf /backup/uploads_$(date +%F).tgz -C /data .
```

## 3. 路线 C：PaaS 托管（Render / Railway / Fly.io）

以 Render 为例：

1. 新建 **Web Service**，连接 GitHub 仓库，Runtime 选 Docker（仓库已有 `Dockerfile`）；
2. 新建 **PostgreSQL**？不适用——本项目用 MySQL，Render 需外接 MySQL（如 PlanetScale / 云数据库）；
3. 环境变量同 2.6；
4. 前端单独建 **Static Site**，构建命令 `npm ci && npm run build`，发布目录 `web/dist`；
5. 把静态站的反向代理指向 Web Service（Render 支持 rewrite，但 `/ws` 长连接需要确认套餐支持）。

现实问题：

- 多数 PaaS 对 WebSocket 长连接有时长/并发限制，语音流式与视频信令容易断；
- 平台不提供 TURN，跨 NAT 视频仍会失败；
- 大陆访问速度不理想。

**结论**：PaaS 适合「先看效果」，长期运营仍建议路线 B。

## 5. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面能开，接口 502 | 后端未起来 / 容器名不对 | `docker compose logs app`；确认 nginx `proxy_pass http://app:8080` |
| 语音按钮点了没反应 | 非 HTTPS，浏览器禁用麦克风 | 必须 `https://`；检查证书是否生效 |
| 一直「正在连接对方」 | 缺 TURN / 安全组未放行 | 配 coturn + 放行 3478 与 49152-65535 |
| WS 连上又立刻断 | Nginx 没配 Upgrade 或超时太短 | 检查 `/ws/` 段 `proxy_read_timeout 3600s` |
| 上传简历 413 | `client_max_body_size` 太小 | 改成 12m，与 `spring.servlet.multipart` 一致 |
| 登录后马上 401 | 多实例 / Redis 未连通 / 时钟偏移 | 单机先确认；NTP 校时 |
| 知识库为空 | 首次启动灌入慢（真实 embedding 需 1~2 分钟） | 等 2 分钟再看 `stats` |
| 生产无账号可登录 | `prod` 默认 `demo-data=false` | 首启设 `APP_DEMO_DATA_ENABLED=true`，建号后关闭 |
| PDF 简历解析失败 | 扫描件无文本层 | 提示用户粘贴文本或上传 docx |

### 6.5 为什么有的 GitHub 仓库上传后「别人点链接就能用」

你在 GitHub 上看到的「打开链接就是网站」，通常不是 GitHub 本身在跑你的程序，而是下面四种机制之一：

| 机制 | 原理 | 能跑后端吗 | 典型场景 |
|---|---|---|---|
| **GitHub Pages** | 把仓库里的静态文件（HTML/CSS/JS）托管到 `用户名.github.io/仓库名` | ❌ 只能静态 | 文档站、纯前端 SPA、作品集 |
| **GitHub Actions + 平台部署** | push 触发 Action，调用 Render/Railway/Fly/Vercel 的 API 或部署钩子 | ✅ | 全栈项目（推荐） |
| **Codespaces / Gitpod 端口转发** | 云端 IDE 把容器端口映射成临时 URL | ✅ 但绑在你的开发容器 | 演示、给面试官看 |
| **Release 附件** | 只是下载 jar/zip，不是网站 | — | 发版 |

**关键判断**：这个项目有 Java 后端、MySQL、Redis、WebSocket，**GitHub Pages 跑不起来**，
因为 Pages 只发静态文件，没有任何服务端进程。

所以正确姿势是：**代码放 GitHub + GitHub Actions 自动部署到托管平台**，链接由平台提供，
push 一次就更新一次——这就是别人看到「上传后就有链接」的真实原因。

#### 6.5.1 最小可行：Render 自动部署（免运维）

1. Render 新建 **Web Service** → 连接 GitHub 仓库 → Runtime 选 **Docker**（仓库已有 `Dockerfile`）；
2. 加环境变量（同 2.6 节，把 `DB_HOST` 指向外部 MySQL，如云数据库/Aiven）；
3. 复制 Deploy Hook，在仓库加一个 Action：

```yaml
# .github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: 触发 Render 部署
        run: curl -fsS -X POST "${{ secrets.RENDER_DEPLOY_HOOK }}"
```

4. 前端可放 Render Static Site，构建命令 `npm ci && npm run build`，发布目录 `web/dist`，
   环境变量设 `VITE_API_BASE=https://你的后端域名/api`、`VITE_WS_BASE=wss://你的后端域名`。

> 前端已支持这两个变量：`VITE_API_BASE` 改变 REST 基址，`VITE_WS_BASE` 改变 WebSocket 基址，
> 前后端不同域也能工作（需要在后端放行跨域，见 6.5.2）。

#### 6.5.2 前后端分离时要注意

| 项 | 处理 |
|---|---|
| REST 跨域 | 后端 `SecurityConfig` 已对 `/api/**` 放开 OPTIONS，生产建议显式配置允许来源 |
| WebSocket 跨域 | 三个端点都 `setAllowedOriginPatterns("*")`，生产建议收紧为你的前端域名 |
| 前端路由 | 静态托管要配置 SPA fallback（`/* → /index.html`） |
| 麦克风权限 | 前端必须 https，且用户首次要授权 |

#### 6.5.3 只想要「一个能点的作品链接」

最省事组合：

- **GitHub Pages 放前端**（免费、永久、自带 https）；
- **Render/Railway 放后端**（免费额度）；
- 视频用公共 STUN，语音/教练走你自己的 Key。

代价是后端免费实例会休眠（首次访问慢 10~30s），且不能放真实用户数据。

## 7. 上线后必须改的三件事

1. **JWT secret**：默认值仅用于开发，生产必须换成随机串；
2. **演示账号密码**：`candidate/123456` 上线后立刻改，或关闭 `demo-data` 并自建账号；
3. **限流与配额**：AI/ASR 都是按量计费，务必在网关层加限流（如 Nginx `limit_req`），
   避免被刷；`agent_trace`、`ai_call_log` 也要设定留存周期。
