# 部署与运行

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 17+ | 已在 JDK 17.0.18 验证 |
| Maven | 3.8+ | 依赖已配置到本地仓库（见 1.1） |
| MySQL | 8.0+ | 仅生产需要；开发用内置 H2 |
| Redis | 6+ | 仅生产多实例部署需要；开发用内存缓存 |
| 浏览器 | Chrome / Edge | 访问 Swagger UI |

### 1.1 Maven 本地仓库位置

本工程 `.mvn/maven.config` 指定依赖下载到 **E 盘**：

```
-Dmaven.repo.local=E:/maven-repository
```

如需改到其他盘，编辑该文件即可（例如 `D:/maven-repository`）。首次构建会自动创建目录并下载依赖；之后离线可用。

## 2. 开发环境启动（零外部依赖）

```bash
cd E:\LearnMore\ai-interview-assistance
mvn spring-boot:run
```

启动后：

| 地址 | 说明 |
|---|---|
| http://localhost:8080/swagger-ui.html | 在线接口文档 |
| http://localhost:8080/h2-console | H2 控制台（JDBC URL：`jdbc:h2:mem:aiinterview`，用户 `sa`，密码空） |
| ws://localhost:8080/ws/interview?token=...&interviewId=... | 实时面试通道 |

开发环境默认使用：

- H2 内存库（每次重启数据清空，启动自动执行 `db/schema.sql`）；
- 本地缓存 `LocalCacheStore`；
- AI 桩 `MockLlmClient`（无需 API Key，返回结构合法的模拟数据）；
- 自动灌入演示数据。

| 用户名 | 密码 | 角色 |
|---|---|---|

### 2.2 切换真实大模型

```bash
set APP_AI_PROVIDER=openai
set APP_AI_BASE_URL=https://api.deepseek.com/v1
set APP_AI_API_KEY=sk-xxxx
set APP_AI_MODEL=deepseek-chat
mvn spring-boot:run
```

任何 OpenAI 兼容接口均可（OpenAI、DeepSeek、通义千问 DashScope 兼容模式、vLLM、Ollama 的 `/v1` 等）。

> `provider` 的取值只有 `mock` / `openai`。`openai` 表示「OpenAI 兼容协议」，DeepSeek、硅基流动、通义都应填 `openai`，
> 靠 `base-url` 与 `model` 区分；填成 `siliconflow` 之类会导致找不到客户端 Bean、应用启动失败。

### 2.3 三个能力的推荐组合（已实测）

| 能力 | 环境变量 | 推荐值 |
|---|---|---|
| 对话 / 出题 / 评分 / Agent | `APP_AI_PROVIDER=openai`<br>`APP_AI_BASE_URL=https://api.deepseek.com/v1`<br>`APP_AI_MODEL=deepseek-chat`<br>`DEEPSEEK_API_KEY=sk-...` | DeepSeek 官方，`deepseek-chat` 支持 function calling |
| RAG Embedding | `APP_EMBEDDING_PROVIDER=openai`<br>`APP_EMBEDDING_BASE_URL=https://api.siliconflow.cn/v1`<br>`APP_EMBEDDING_MODEL=BAAI/bge-m3`<br>`APP_EMBEDDING_API_KEY=sk-...` | 硅基流动，中文语义召回好，通常有免费额度 |
| 语音转写 | `APP_ASR_PROVIDER=openai`<br>`APP_ASR_BASE_URL=https://api.siliconflow.cn/v1`<br>`APP_ASR_MODEL=FunAudioLLM/SenseVoiceSmall`<br>`APP_ASR_API_KEY=sk-...` | 硅基流动 SenseVoice；或 OpenAI `whisper-1` |

三家 Key 不要混用：DeepSeek 的 Key 发给硅基流动会 401。

### 2.4 三种配置密钥的方式

**方式一：IDEA Run Configuration（推荐给本地开发）**

在 `Run → Edit Configurations → AiInterviewApplication` 里：

- `Active profiles` 只填 `dev`（**不要**把 Key 填在这里，填了不会被读取）；
- `Environment variables` 里逐行添加 `DEEPSEEK_API_KEY`、`APP_AI_PROVIDER`、`APP_ASR_*`、`APP_EMBEDDING_*`。

> 常见错误：把 `KEY=value` 粘贴进 `Active profiles` 输入框。Spring 会把它当成 profile 名，
> 结果是既不报错也不生效，日志里只会看到 `The following 1 profile is active: "dev"`。

**方式二：本地密钥文件（命令行启动）**

```powershell
Copy-Item config\secrets.example.env config\secrets.env
notepad config\secrets.env          # 填入真实 Key
powershell -ExecutionPolicy Bypass -File scripts\run-local.ps1
```

`config/secrets.env` 已在 `.gitignore` 中；`run-local.ps1` 只把变量注入当前进程，不会打印值。

**方式三：系统/用户环境变量**

```powershell
setx DEEPSEEK_API_KEY "sk-..."
setx APP_AI_PROVIDER "openai"
```

`setx` 只对新开的终端和进程生效，改完要重启应用。

### 2.5 首次启动会慢：演示数据在灌知识库

真实 embedding 下，启动时要把 9 篇资料切成 15 个分块并逐个向量化，需要几十秒到两分钟。
`/actuator/health` 在 Web 服务就绪时就返回 UP，此时灌入可能还没完成，
`/api/v1/knowledge/stats` 会看到 `documentCount` 逐步增长（4 → 9）。
排查「知识库为空」时先确认灌入是否仍在进行，再去看日志里的
`知识库索引重建完成 documents=9 chunks=15`。

## 3. 快速体验一次完整面试（curl）

### 3.1 登录

```bash
curl -X POST http://localhost:8080/api/v1/auth/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"candidate\",\"password\":\"123456\"}"
```

返回：

```json
{"code":0,"message":"成功","data":{"accessToken":"eyJhbGciOi...","tokenType":"Bearer","expiresInSeconds":14400,
"user":{"id":"...","username":"candidate","role":"CANDIDATE"}},"timestamp":...}
```

后续请求都带上：`-H "Authorization: Bearer <accessToken>"`。

### 3.2 查询岗位与简历

```bash
curl http://localhost:8080/api/v1/jobs -H "Authorization: Bearer <token>"
curl http://localhost:8080/api/v1/resumes/my -H "Authorization: Bearer <token>"
```

### 3.3 创建面试

```bash
curl -X POST http://localhost:8080/api/v1/interviews ^
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" ^
  -d "{\"positionId\":\"<岗位id>\",\"resumeId\":\"<简历id>\",\"mode\":\"TECH\",\"totalQuestions\":5}"
```

### 3.4 开始并获取当前题

```bash
curl -X POST http://localhost:8080/api/v1/interviews/<面试id>/start -H "Authorization: Bearer <token>"
```

### 3.5 提交答案

```bash
curl -X POST http://localhost:8080/api/v1/interviews/<面试id>/answers ^
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" ^
  -d "{\"questionId\":\"<题目id>\",\"answer\":\"HashMap 底层是数组+链表，JDK8 引入红黑树...\",\"thinkingSeconds\":60}"
```

最后一题提交后返回 `finished=true` 与 `reportId`。

### 3.6 查看报告

```bash
curl http://localhost:8080/api/v1/interviews/<面试id>/report -H "Authorization: Bearer <token>"
```

### 3.7 WebSocket 方式（可选）

使用任意 WebSocket 客户端连接：

```
ws://localhost:8080/ws/interview?token=<accessToken>&interviewId=<面试id>
```

协议（JSON）：

```json
{"type":"START"}
{"type":"ANSWER","content":"我的回答...","thinkingSeconds":45}
{"type":"PING"}
{"type":"SWITCH"}
```

服务端推送：

```json
{"type":"CONNECTED","data":{"interviewId":"..."}}
{"type":"QUESTION","data":{"questionId":"...","seq":1,"totalQuestions":5,"content":"..."}}
{"type":"SCORE","data":{"score":82,"comment":"...","finished":false,"nextQuestion":{...}}}
{"type":"FINISHED","data":{"reportId":"..."}}
```

### 5.3 Nginx 反向代理（含 WebSocket）

```nginx
server {
    listen 80;
    server_name interview.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /ws/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 600s;
    }
}
```

### 5.5 视频与 AI 能力部署

- **必须 HTTPS/WSS**：浏览器只允许安全上下文使用摄像头/麦克风；Nginx 的 `/ws/` 需要 `Upgrade`/`Connection` 头（见 5.3）。
- **STUN/TURN**：默认只配置公共 STUN。跨运营商/严格 NAT 需要自建 coturn，并把地址加入 `app.video.ice-servers`；当前配置只支持 URL 字符串，TURN 用户名/密码需扩展配置结构（`IceServerVO` 已预留字段）。
- **信令单机内存**：`CallSessionRegistry` 与 `WsSessionRegistry` 一样是单实例状态；多实例部署需要网关粘性会话或 Redis 广播。
- **RAG 索引**：BM25 索引在 JVM 内构建，适合万级分块；文档量很大时应换 pgvector/Milvus/ES，并做增量更新。
- **Agent 模型**：使用 `deepseek-chat`（支持 function calling）；`deepseek-reasoner` 不支持 tools。

## 6. 常见问题
| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `Table "SYS_USER" not found` | 未启用 dev profile 或 schema 未执行 | 使用 `--spring.profiles.active=dev`，或手动执行 schema |
| 登录 401 | 未带 `Authorization: Bearer` 或令牌过期 | 重新登录 |
| 403 无权限 | 角色不足（如候选人访问管理端） | 使用对应角色账号 |
| 创建面试 409 | 岗位非 OPEN、简历未解析完成 | 先发布岗位；等待简历 `status=PARSED` |
| AI 调用失败 | 未配置 Key 或网络不通 | 查看 `ai_call_log`，或切回 `provider=mock` |
| 上传 docx 解析为空 | 文件为扫描件/加密文档 | 直接粘贴文本创建简历 |
| 中文乱码（Windows 控制台） | 控制台编码 GBK | `chcp 65001`，或忽略（接口返回 UTF-8 正常） |
| Maven 下载慢/失败 | 网络受限 | 检查 `.mvn/maven.config` 指向的仓库；或预先 `mvn dependency:go-offline` |

## 7. 日志与监控

- 应用日志：控制台 + `logging.level.com.aiinterview=DEBUG`（开发）；
- MyBatis SQL：`application.yml` 中 `log-impl: StdOutImpl`（开发）；
- AI 调用：`ai_call_log` 表；
- 操作审计：`sys_operation_log` 表；
- 健康检查：`/actuator/health`（已接入，仅暴露 health/info 两个端点）。
